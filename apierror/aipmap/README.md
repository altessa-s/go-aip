# aipmap

```go
import "github.com/altessa-s/go-aip/apierror/aipmap"
```

Package `aipmap` holds the [`apierror`](../) rules for the sentinel errors of the go-aip packages. Pass them to a mapper after the service's
own rules:

```go
mapper, err := apierror.NewMapper(
	apierror.WithRules(myRules...),
	apierror.WithRules(aipmap.Rules()...),
	apierror.WithDefaultDomain("library.example.com"))
```

It is a separate package so that `apierror` depends on go-atlas-core/errors only; importing `aipmap` links fieldmask, fieldbehavior, fieldinfo,
etag, validateonly, filter (CEL), orderby, projection, listing, listing engine work budgets, pagetoken, batch, softdelete, requestid,
unreachable, state and resourcename. None of them imports `apierror` or `aipmap`.

"Exposed" publishes the error's text, which describes the client's input; with a `coreerrs.FieldError` in the chain (listing wraps these
errors under `filter`, `orderBy`, `pageToken` or `pageSize`; fieldmask under `updateMask.paths[i]`; etag under its field, such as
`book.etag`) the message is `<field>: <reason>` and a `BadRequest` field violation names the field with the rule's reason.

¹ **One field violation per listed field.** An error that lists several fields gets one `BadRequest` field violation per entry, its path
as produced (field paths are never rewritten) and a reason per entry:

| Error                                                                                 | Field violation reason                                                                                                                                   |
|---------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| `fieldinfo.ViolationError` (each `Violation`)                                         | `FormatReason(Format)`: `INVALID_UUID4`, `INVALID_IPV4`, `INVALID_IPV6`, `INVALID_IPV4_OR_IPV6`, a custom format upper-cased (`email` → `INVALID_EMAIL`) |
| `fieldinfo.ValueError` inside a FieldError                                            | `FormatReason(Format)` on the FieldError's field                                                                                                         |
| `fieldbehavior.BehaviorViolationError`, behavior set                                  | `BehaviorReason(Behavior)`: `REQUIRED_FIELD`, `IMMUTABLE_FIELD`, `IDENTIFIER_FIELD`, `OUTPUT_ONLY_FIELD`, ...                                            |
| `fieldbehavior.BehaviorViolationError`, `FIELD_BEHAVIOR_UNSPECIFIED` (AIP-202 format) | `FormatReason` of the violation's `Format`, `INVALID_FIELD_FORMAT` when it is empty                                                                      |
| `update.BehaviorError`, `StrictError`                                                 | `BehaviorReason(Behavior)`, or the rule's reason for a violation without a behavior (an unknown or malformed path)                                       |

A FieldError whose cause is such an error (a batch `ItemError` builds one, `requests[2]`) prefixes every path with its field
(`requests[2].uid`), and its `<field>: <reason>` is the message; an entry without a path names the enclosing field, or no field at all.
`aipmap.FormatReason` and `aipmap.BehaviorReason` expose the reason scheme for services that build their own violations.
Everything not listed falls through to `apierror.DefaultRules()`: `etag.ErrMismatch` wraps `coreerrs.ErrConflict` (ABORTED `VERSION_CONFLICT`, AIP-154),
`backend/sqlbase.ErrTimeout` comes with `coreerrs.ErrUnavailable` (UNAVAILABLE) or as a FieldError on `filter` (INVALID_ARGUMENT), a list query whose
caller's context ended returns that context's error (CANCELLED or DEADLINE_EXCEEDED) with the backend error hidden (`apierror.Classify`),
`sqlbase.ErrScope`, `ErrCorruptRecord`, `ErrInvalidTableName` and `ErrInvalidColumnName` are configuration or server faults (INTERNAL as unknown
errors), the `backend/mongo` sentinels map the same way (`ErrTimeout` like `sqlbase.ErrTimeout`; `ErrScope`, `ErrCorruptRecord` and the codec errors
INTERNAL), `backend/memory.ErrWorkBudget` wraps `listing.ErrWorkBudget`, `requestid.ErrStoreFull` comes wrapped in `ErrStore` (UNAVAILABLE), the
translator errors of filter, orderby and projection wrap the sentinels above (the meili version check wraps `filter.ErrInvalidOptions`, INTERNAL;
`orderby.ErrTooManySortKeys` wraps `ErrUnsupportedOrdering`), the error types not listed (`batch.ItemError`, `update.MaskPathError`,
`unreachable.SourceError`) keep the classification of their cause, and the sentinels that already carry a canonical class keep it: `batch.ErrNotFound`,
`softdelete.ErrNotFound` and `ErrAlreadyDeleted` (NOT_FOUND), `softdelete.ErrNotDeleted` (ALREADY_EXISTS), `requestid.ErrStore` (UNAVAILABLE).

The test `TestEverySentinelIsListed` parses the module's core packages and fails for an exported `Err*` variable or error type that its table
does not list with an intended code and reason, so a new sentinel cannot reach clients as an accidental INTERNAL. The sentinels of the
backend modules are listed the same way by `TestEveryBackendSentinelIsListed` in the test-only module
[integration/crossbackend](../../integration/crossbackend/README.md), so that the root module requires no backend module; `backend/mongo`,
which that module does not require, checks its own in `errors_test.go`.

### Decisions

* **Limits are INVALID_ARGUMENT**, not RESOURCE_EXHAUSTED: the request itself is too large and retrying it fails the same way.
* **A work budget is RESOURCE_EXHAUSTED**: the request is valid but would cost more than the server allows for the data it holds.
* **Allow-list refusals are INVALID_ARGUMENT** (`*_NOT_ALLOWED`), as AIP-160 and AIP-132 treat unsupported filter and order fields; a
  service that derives allow-lists from authorization adds its own PERMISSION_DENIED rule before these.
* **A replayed requestid failure is the original status**: `requestid.ReplayedError` carries the stored `google.rpc.Status`, which the
  rule converts with `apierror.FromProto` (a stored status without `ErrorInfo` keeps its code and message, the reason becomes the code name).
* **All-failed batches** are ABORTED as AIP-233 to AIP-235 require. The prescribed message names the operation metadata type, which only
  the service knows: return `apierror.New(code.Code_ABORTED, batch.AllFailedMessage(...))` for the exact text; the rule's message is the
  generic form.
* **A state transition exposes its text**: it names the current and target states, which are the resource's own output fields.
* **Server faults are INTERNAL**: a missing policy, step, registry entry or annotation, an etag helper given a message without an etag
  field, a validate_only field of the wrong type — none of it is the client's to fix.
* **Nesting depth is the client's**: the fieldbehavior and fieldinfo walks descend populated (client-sent) messages, so exceeding their depth
  limit is INVALID_ARGUMENT `MESSAGE_TOO_DEEP`, like the other limits.
* **An etag mismatch is the canonical conflict**: ABORTED `VERSION_CONFLICT` from the default rules, as AIP-154 requires and as go-atlas
  reports it; a missing required etag (`ETAG_REQUIRED`) and a malformed one (`INVALID_ETAG`) are INVALID_ARGUMENT on the etag field.
* **Ordering of overlapping sentinels**: the fieldmask limit errors also match `ErrInvalidPath`, a strict update-mask error also carries
  `ErrBehaviorViolation`, and `ErrUnencryptedToken` wraps `ErrInvalidToken`; the more specific rule comes first.

The reasons are exported constants (`ReasonInvalidFilter`, ...): clients may match them.
